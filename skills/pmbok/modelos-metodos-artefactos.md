# Modelos, métodos y artefactos

## Cómo usar este catálogo
Modelo = estrategia de pensamiento para explicar un fenómeno (para diagnosticar "por qué pasa esto"); método = medio concreto para producir un efecto o entregable (para "cómo lo hago"); artefacto = plantilla o salida resultante (para "dónde lo registro"). Adopta solo lo que aporte valor real; evita duplicar esfuerzo o generar información engañosa.

## Modelos

### Liderazgo situacional
- **Situational Leadership® II** (Blanchard): competencia + compromiso del individuo — usar cuando el estilo (dirigir, coaching, apoyar, delegar) debe evolucionar con su madurez.
- **Modelo OSCAR** (Whittleworth/Gilbert): 5 pasos de coaching (resultado, situación, opciones, acciones, revisión) — usar en sesiones de mentoría con plan de desarrollo.

### Comunicación
- **Comunicación intercultural** (Browaeys/Price): el mensaje se filtra por idioma, experiencia y estereotipos de emisor/receptor — usar con equipos multiculturales.
- **Efectividad de los canales de comunicación** (Cockburn, sobre riqueza de Daft/Lengel): ordena canales por riqueza de información — usar para elegir cara a cara vs. texto según complejidad.
- **Brecha de ejecución y de evaluación** (Norman): ¿el usuario puede hacer lo que espera? ¿entiende cómo interactuar? — usar al diseñar procesos o entregables usables.

### Motivación
- **Factores de higiene y de motivación** (Herzberg): logro/crecimiento motivan; salario/políticas solo evitan insatisfacción — usar al diseñar recompensas.
- **Motivación intrínseca vs. extrínseca** (Pink): autonomía, dominio, propósito — usar en trabajo complejo/creativo con salario ya justo.
- **Teoría de las necesidades** (McClelland): logro, poder, afiliación como impulsores — usar para adaptar el reconocimiento a cada persona.
- **Teoría X, Y y Z** (McGregor; Z de Maslow/Ouchi): de supervisión estricta a confianza/coaching a propósito — usar para elegir estilo de gestión según autonomía del equipo.

### Cambio
- **Gestión del Cambio en las Organizaciones** (guía PMI): formular, planificar, implementar, gestionar transición, mantener el cambio — usar como marco general de change management.
- **Modelo ADKAR®** (Hiatt): concienciación, deseo, conocimiento, capacidad, refuerzo — usar para diagnosticar en qué paso se atasca alguien.
- **8 Pasos para Liderar el Cambio** (Kotter): top-down, de crear urgencia a anclar en la cultura — usar en transformaciones organizacionales grandes.
- **Modelo de Virginia Satir**: statu quo, elemento extraño, caos, idea transformadora, práctica, nuevo statu quo — usar para explicar la caída de desempeño tras un cambio.
- **Modelo de Transición** (Bridges): terminar/perder, zona neutral, nuevo comienzo — usar para separar el cambio (situacional) de la transición (psicológica).

### Complejidad
- **Marco Cynefin** (Snowden): 5 contextos — obvio, complicado, complejo, caótico, desordenado — usar para diagnosticar el tipo de toma de decisiones que aplica.
- **Matriz de Stacey**: cruza incertidumbre de requisitos vs. de tecnología — usar para clasificar el proyecto (sencillo/complicado/complejo/caótico) y elegir enfoque de entrega.

### Desarrollo del equipo de proyecto
- **Escalera de Tuckman**: formación, turbulencia, normalización, desempeño, (disolución) — usar para entender la fricción inicial de un equipo nuevo.
- **Desempeño del Equipo de Drexler/Sibbet**: orientación, confianza, meta, compromiso, implementación, alto desempeño, renovación — usar como checklist de madurez del equipo.

### Otros modelos
- **Modelo de Conflicto** (Thomas-Kilmann): confrontación, colaboración, compromiso, estabilización/complacencia, imposición, retirada — usar para elegir cómo abordar un conflicto según poder y relación.
- **Negociación** (Covey, "Ganar-Ganar"): carácter, confianza, enfoque en la otra parte — usar en cualquier negociación con interesados o proveedores.
- **Planificación** (Boehm): compara tiempo de planificación vs. riesgo de retrabajo — usar para hallar el punto óptimo de cuánto planificar.
- **Grupos de Procesos**: inicio, planificación, ejecución, monitoreo y control, cierre — usar como estructura organizativa en un enfoque basado en procesos (no son fases).
- **Modelo de Prominencia** (Mitchell/Agle/Wood): poder, legitimidad, urgencia — usar para priorizar a qué interesados atender primero.

## Métodos

### Recopilación y análisis de datos
- **Análisis de alternativas**: compara opciones para elegir cómo ejecutar el trabajo.
- **Análisis de supuestos y restricciones**: verifica coherencia entre ellos y los planes.
- **Estudios comparativos (benchmarking)**: compara contra organizaciones similares — usar para fijar metas de desempeño.
- **Plazo de recuperación**: tiempo para recuperar la inversión.
- **Tasa interna de retorno (IRR)**: rendimiento anual proyectado — usar para comparar rentabilidad entre proyectos.
- **Retorno de la inversión (ROI)**: % de retorno sobre la inversión inicial.
- **Valor actual neto (NPV)**: valor presente de beneficios futuros — usar cuando importa el valor del dinero en el tiempo.
- **Análisis costo-beneficio**: compara beneficios contra costos.
- **Hoja de verificación**: lista de control para recopilar y categorizar datos.
- **Costo de la calidad**: suma costos de prevención, evaluación e incumplimiento.
- **Análisis mediante árbol de decisiones**: calcula implicaciones de opciones múltiples bajo incertidumbre.
- **Análisis del valor ganado (EVM)**: mide desempeño de costo y cronograma con métricas integradas.
- **Valor monetario esperado (EMV)**: probabilidad × impacto económico — usar para cuantificar riesgos.
- **Pronóstico**: estima condiciones futuras (cualitativo, cuantitativo o causal).
- **Diagrama de influencias**: representa influencias causales y cronología de eventos.
- **Evaluación del ciclo de vida**: mide impacto ambiental total de un producto — usar en proyectos con criterios de sostenibilidad.
- **Análisis de hacer o comprar**: compara fabricar vs. adquirir externamente.
- **Matriz de probabilidad e impacto**: prioriza riesgos según su probabilidad e impacto.
- **Análisis de procesos**: revisión sistemática de pasos y procedimientos.
- **Análisis de regresión**: relaciona variables de entrada con resultados de salida.
- **Análisis de reserva**: evalúa si la reserva cubre el riesgo restante.
- **Análisis de causa raíz**: encuentra la causa subyacente de una variación o defecto.
- **Análisis de sensibilidad**: identifica qué riesgos tienen mayor impacto potencial.
- **Simulación (Monte Carlo)**: iteraciones de un modelo para obtener distribución de probabilidad de resultados.
- **Análisis de interesados**: recopila información cuantitativa y cualitativa de interesados.
- **Análisis FODA**: fortalezas, oportunidades, debilidades y amenazas.
- **Análisis de tendencias**: modelos matemáticos sobre resultados históricos.
- **Mapeo del flujo de valor**: documenta y mejora el flujo lean de información o materiales.
- **Análisis de variación**: compara línea base contra desempeño real.
- **Análisis de escenarios "¿Qué pasa si...?"**: evalúa efecto de escenarios hipotéticos sobre los objetivos.

### Estimación
- **Agrupamiento de afinidad**: clasifica por semejanza (t-shirt sizing, Fibonacci) — usar para estimar rápido en grupo.
- **Estimación análoga**: usa datos históricos de un proyecto similar.
- **Punto de función**: mide funcionalidad comercial de un sistema — usar para dimensionar software.
- **Estimación multipunto (PERT)**: promedio ponderado de optimista/pesimista/más probable.
- **Estimación paramétrica**: algoritmo con datos históricos y parámetros del proyecto.
- **Estimación relativa**: compara con trabajos similares en esfuerzo y complejidad.
- **Estimación puntual**: un único valor más probable, sin rango.
- **Estimación por punto de historia**: puntos de esfuerzo relativos por historia de usuario.
- **Delphi de banda ancha**: rondas iterativas de estimación individual hasta converger (incluye planning poker).

### Reuniones y eventos
- **Perfeccionamiento del backlog**: refina y repriorizada el trabajo pendiente antes de la siguiente iteración.
- **Conferencia de oferentes**: reunión con posibles vendedores antes de licitar.
- **Comité de control de cambios**: revisa, aprueba o rechaza cambios propuestos.
- **Reunión diaria de pie**: breve sincronización diaria de avance y obstáculos.
- **Planificación de la iteración**: aclara ítems, criterios de aceptación y esfuerzo del próximo sprint.
- **Revisión de la iteración**: demuestra el trabajo hecho al cierre de cada sprint.
- **Lanzamiento (kickoff)**: alinea expectativas al inicio de proyecto, fase o iteración.
- **Lecciones aprendidas**: identifica y comparte conocimiento adquirido al cierre.
- **Reunión de planificación**: crea o revisa un plan y asegura compromiso.
- **Cierre del proyecto**: obtiene aceptación final del alcance entregado.
- **Revisión del proyecto**: evalúa estado y valor entregado al final de una fase.
- **Planificación de la liberación**: plan de alto nivel antes de un release.
- **Retrospectiva**: taller periódico para mejorar proceso y producto.
- **Revisión del riesgo**: analiza riesgos existentes e identifica nuevos.
- **Reunión de estatus**: intercambia información de progreso periódicamente.
- **Comité de dirección**: interesados sénior deciden fuera de la autoridad del equipo.

### Otros métodos
- **Mapeo de impacto**: hoja de ruta visual que conecta objetivos de negocio con funcionalidades.
- **Modelado**: representaciones simplificadas (prototipos, diagramas) — usar para detectar lagunas antes de construir.
- **Puntuación Neta del Promotor (NPS®)**: mide disposición del cliente a recomendar el producto.
- **Esquema de priorización**: prioriza con criterios explícitos (multicriterio, MoSCoW).
- **Período de Tiempo Preestablecido (timebox)**: bloque corto y fijo de tiempo — usar en iteraciones ágiles.

## Artefactos

### Estrategia
- **Caso de negocio**: propuesta de valor con beneficios financieros y no financieros — se usa al justificar el inicio del proyecto.
- **Lienzo de modelo de negocio**: resumen visual de propuesta de valor, infraestructura, clientes y finanzas — se usa en lean startup.
- **Informe del proyecto**: visión general de alto nivel de objetivos y entregables.
- **Acta de constitución del proyecto**: autoriza formalmente el proyecto y da autoridad al director.
- **Declaración de la visión del proyecto**: descripción concisa que inspira al equipo.
- **Hoja de ruta**: línea de tiempo de alto nivel con hitos y puntos de decisión.

### Bitácoras y registros
- **Registro de supuestos**: documenta supuestos y restricciones durante todo el proyecto.
- **Lista de trabajo pendiente (backlog)**: lista ordenada y priorizada del trabajo a realizar.
- **Registro de cambios**: lista de cambios presentados y su estado.
- **Registro de incidentes**: da seguimiento a condiciones activas que impactan objetivos.
- **Registro de lecciones aprendidas**: conocimiento capturado para mejorar desempeño futuro.
- **Backlog ajustado al riesgo**: trabajo priorizado para abordar amenazas y oportunidades.
- **Registro de riesgos**: responsable, probabilidad, impacto y respuesta de cada riesgo.
- **Registro de interesados**: información, evaluación y clasificación de interesados.

### Planes
- **Plan de control de cambios**: establece el comité y el sistema de control de cambios.
- **Plan de gestión de las comunicaciones**: cómo, cuándo y por quién se difunde la información.
- **Plan de gestión de los costos**: cómo se planifican y controlan los costos.
- **Plan de iteración**: plan detallado de la iteración actual.
- **Plan de gestión de las adquisiciones**: cómo se adquieren bienes y servicios externos.
- **Plan para la dirección del proyecto**: documento integrador que describe ejecución, monitoreo, control y cierre.
- **Plan de gestión de la calidad**: cómo se implementan políticas y objetivos de calidad.
- **Plan de liberación**: expectativas de fechas y alcance a través de iteraciones.
- **Plan de gestión de los requisitos**: cómo se analizan y gestionan los requisitos.
- **Plan de gestión de los recursos**: cómo se adquieren y controlan los recursos.
- **Plan de gestión de los riesgos**: cómo se estructuran las actividades de gestión de riesgos.
- **Plan de gestión del alcance**: cómo se define y valida el alcance.
- **Plan de gestión del cronograma**: criterios para desarrollar y controlar el cronograma.
- **Plan de involucramiento de los interesados**: estrategias para promover su participación.
- **Plan de pruebas**: qué se prueba, cómo, y con qué procesos.

### Diagramas jerárquicos
- **Estructura de desglose de la organización (OBS)**: relaciona actividades con unidades organizacionales.
- **Estructura de desglose del producto (PBS)**: componentes y entregables del producto.
- **Estructura de desglose de recursos (RBS)**: recursos por categoría y tipo.
- **Estructura de desglose del riesgo (RBS)**: fuentes posibles de riesgo.
- **Estructura de desglose del trabajo (EDT/WBS)**: descomposición jerárquica del alcance total — base de la planificación.

### Líneas base
- **Presupuesto**: estimación aprobada de costo del proyecto o sus componentes.
- **Cronograma de hitos**: hitos con fechas planificadas — se usa con interesados sénior.
- **Línea base para la medición del desempeño**: alcance, cronograma y costo integrados — se usa con EVM.
- **Cronograma del proyecto**: actividades con fechas, duraciones, hitos y recursos.
- **Línea base del alcance**: enunciado de alcance, EDT y diccionario aprobados.

### Datos e información visuales
- **Diagrama de afinidad**: agrupa muchas ideas para revisión y análisis.
- **Gráfica burndown/burnup**: trabajo pendiente o realizado en un período.
- **Diagrama de causa y efecto (Ishikawa)**: rastrea un efecto no deseado hasta su causa raíz.
- **Diagrama de flujo acumulativo (CFD)**: completado, en curso y en backlog en el tiempo — se usa en kanban.
- **Diagrama de tiempo de ciclo**: tiempo de ciclo promedio de elementos completados.
- **Tableros (dashboards)**: gráficos con progreso o rendimiento del proyecto.
- **Diagrama de flujo**: entradas, acciones y salidas de un proceso.
- **Diagrama de Gantt**: barras horizontales de actividades contra fechas.
- **Histograma**: representación gráfica de datos numéricos.
- **Radiador de información**: indicación visible y física de información al resto de la organización.
- **Diagrama de tiempo de entrega (lead time)**: tendencia del tiempo de entrega de ítems terminados.
- **Matriz de priorización**: esfuerzo vs. valor en cuatro cuadrantes.
- **Diagrama de red del cronograma**: relaciones lógicas entre actividades — base de la ruta crítica.
- **Matriz de trazabilidad de requisitos**: vincula requisitos desde su origen hasta los entregables.
- **Matriz de Asignación de Responsabilidades (RAM/RACI)**: recursos asignados a paquetes de trabajo.
- **Diagrama de dispersión**: relación entre dos variables.
- **Curva S**: costos acumulados en el tiempo.
- **Matriz de evaluación del involucramiento de los interesados**: compara nivel actual vs. deseado.
- **Story map**: modelo visual de características del producto — visión holística de qué y por qué se construye.
- **Diagrama de rendimiento (throughput)**: entregables aceptados a lo largo del tiempo.
- **Caso de uso**: cómo un usuario interactúa con un sistema para lograr un objetivo.
- **Mapa del flujo de valor**: documenta y mejora el flujo lean de información o materiales.
- **Diagrama de velocidad**: tasa a la que se producen, validan y aceptan entregables.

### Informes
- **Informe de calidad**: temas de gestión de calidad y acciones correctivas.
- **Informe de riesgos**: resumen progresivo de riesgos individuales y nivel de riesgo global.
- **Informe de estado**: avance desde el último informe y pronósticos de costo/cronograma.

### Acuerdos y contratos
- **Contratos de precio fijo** (FFP, FPIF, FP-EPA): precio fijo para alcance bien definido.
- **Contratos de costo reembolsable** (CPAF, CPFF, CPIF): paga costos reales más honorarios — usar cuando el alcance es incierto o cambiante.
- **Contrato por tiempo y materiales (T&M)**: tarifa fija sin enunciado preciso del trabajo — usar para aumento de personal.
- **Contrato de entrega indefinida cantidad indefinida (IDIQ)**: cantidad indefinida con límites y plazo.
- **Otros acuerdos** (MOU, MOA, SLA, BOA): entendimientos definidos cuando no aplica un contrato de compra-venta.

### Otros artefactos
- **Lista de actividades**: tabla de actividades del cronograma con descripción y alcance.
- **Documentos de las licitaciones** (RFI, RFQ, RFP): solicitan propuestas de posibles vendedores.
- **Métricas**: describen un atributo y cómo medirlo.
- **Calendario del proyecto**: días laborables y turnos disponibles para actividades programadas.
- **Documentación de requisitos**: registro de requisitos con categoría, prioridad y criterios de aceptación.
- **Acta de constitución del equipo de proyecto**: valores y pautas operativas — fija expectativas de comportamiento.
- **Historia de usuario**: breve descripción de un resultado para un usuario específico.
